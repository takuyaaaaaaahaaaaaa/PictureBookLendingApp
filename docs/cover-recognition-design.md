# 表紙検索の設計

表紙検索はえほん台帳の製品アプリに統合した機能です。`Experiments/CoverRecognition` に残るモデル比較・更新可能kNNは独立実験であり、製品アプリの実装とは分けています。ブランチ名に残る `poc/` は作業履歴です。名称の整理は、精度評価や配布条件の確認完了を意味しません。

## 検索と登録

- 固定FastViT T8 HeadlessをCore MLで実行し、256×256 RGBから768次元の正規化特徴量を生成。モデルの重みを学習する機能ではありません。
- 登録撮影は外カメラ。全画面で切り抜き結果を確認し、四隅を調整・台形補正した写真を採用します。保存前の撮り直し・キャンセルでは既存写真を変更しません。
- 表紙検索はインナーカメラ。約1秒間隔、同時に1要求を処理。四隅検出を必須条件にせず、元画像と自動補正画像を照合します。
- 類似度0.70以上の最大5候補。同じ先頭候補が2回連続したら停止して候補を表示します。0.70は校正済み確率ではありません。候補選択後も利用者・貸出枠の選択が必要で、貸出を自動確定しません。
- 同じ表紙の複本は管理番号で選択します。候補がないときは閉じて通常検索へ戻れます。

## 準備への入口

設定の「お試し機能 → 表紙検索の準備」で、準備状況と未処理の再試行を確認できます。貸出の「表紙で検索」は、準備済みの本があればカメラを開き、まだなければ同じ準備画面へ案内します。確認中と0件を区別し、一部準備済みなら残りの処理を待たず検索できます。画像のない本は未処理のままなので図書管理で画像を追加します。

自動の不足・変更分準備は維持し、準備画面を閉じても継続します。外部画像の取得・再取得には通信が必要です。ニューラルネットワークの再学習や、準備済み全件の強制再生成を行う操作ではありません。

## 保存データと責務

| データ | 保存先・責務 | 再生成・削除 |
| --- | --- | --- |
| 採用した写真 | 既存の `BookImages`、Bookのファイル名参照 | 既存の図書画像バックアップ対象 |
| モデル特徴量 | `CoverFeatures-v1.json`、engine actor | モデル/前処理版・画像元変更で再生成。蔵書削除時に除外 |
| 確認済み範囲・画像元・指定ID | `CoverFeatures-v1.json.crops.json` | ユーザーの選択なのでバックアップ対象 |
| 範囲指定時の画像 | `CoverFeatures-v1.json.crop-images/<UUID>.image` | 範囲差し替え・蔵書削除に合わせて削除 |
| 検索中のカメラ画像 | メモリ上のみ | 検索画面終了で保持を終える。認識サーバーへの送信なし |

画像をbase64として全件JSONに保存していた旧形式は、最初のengineアクセスで個別画像ファイルへ移行します。画像を書いてからメタデータを原子的に更新し、書き込みに失敗した場合は旧メタデータを保持します。索引ファイルの読み込みと画像処理はMainActorの初期化では行いません。

## バックアップ・復元

バックアップ形式を2へ更新し、既存の蔵書・画像データに任意の `coverSearchPreparation` アーカイブを追加します。アーカイブ内部にも形式番号を持ち、書籍ID、選択範囲、画像元、範囲指定時の画像を保存します。再生成可能な特徴ベクトルは保存しません。Domain/Modelはアーカイブの中身を解釈せず、App層がengineを通じて読み書きします。

- 書き出し時はバックアップ対象の画像と現在の画像・範囲指定が対応するものだけを含めます。
- 読み込み時は、アーカイブの形式・画像・矩形を検証してから蔵書を置き換えます。
- 復元先ではファイル更新日時が変わるため、書籍IDと画像参照を照合して新しい画像元に結び直します。確認済み写真に自動の再切り抜きを適用しません。
- 既存の索引は無効化して再生成します。復元前の取得処理が遅れて終わっても、古いカタログ世代の結果は保存しません。
- 形式1のバックアップも読めます。ただし当時保存されていなかった範囲指定は復元できないため、再調整が必要な旨を表示します。形式1のみ対応する旧アプリは形式2を拒否し、調整情報を黙って落として読み書きしません。
- 蔵書本体の復元後に調整情報の保存だけが失敗した場合は、蔵書復元済みであることと再試行の必要性を区別して通知します。

## 起動と並行処理

起動・蔵書変更時は準備済み特徴量を再利用し、不足・変更分だけ生成します。画面表示は準備完了を待ちません。完全な蔵書読み込みに失敗した場合は索引の整理を実行せず、空の蔵書と区別します。重複した準備要求は最新の蔵書を待機させ、復元で処理世代が変わった古い要求は結果や進捗を反映しません。待機処理を起動する直前にも新しい要求の有無を確認します。

初回に多数の画像を準備すると、CPU・ディスクと、URL書影の場合は通信を使います。園の200冊以上での起動時の操作負荷は未計測です。「画面を待たせない」と「負荷がない」は異なります。

## カメラの終了・中断・回転

画面終了でセッションを停止し、古い検索試行の結果は採用しません。実行時エラー・利用中断はセッション単位で監視し、停止と再試行案内を一度だけ通知します。停止・破棄で監視を解除し、別セッションや終了済み画面からの通知を無視します。

プレビューと入力画像は左右反転を無効化し、画面の向きに合わせます。180度回転でサイズが変わらない場合も、表示中の向き確認で追従します。重力基準のRotationCoordinatorへは移行していません。実機での中断復帰・180度回転・発熱は引き続き確認が必要です。

## 画像の採用と削除

撮影写真を基本として優先し、写真がある状態の自動入力では置換確認を表示します。フォーム内の新規画像はドラフトとして追跡し、キャンセル・リセット・保存時に未採用分を削除します。登録写真は従来から蔵書バックアップに含まれます。今回追加するのは確認済み範囲と検索用の別保存コピーです。

図書単体の削除は、保存済みの全蔵書から参照を確認してBookレコードを削除し、その写真を他の図書が参照していなければ登録写真も削除します。共有写真は最後の参照が削除されるまで残します。図書データを削除する端末初期化では、全Bookの削除が完了した後、`BookImages`内の旧写真・孤立写真も削除します。図書を削除しない初期化では登録写真も残します。写真を差し替えただけの旧ファイルは単体削除の対象外ですが、図書データの初期化で回収します。

検索索引・特徴量・確認済み範囲は残る蔵書に合わせて保存し直し、不要な検索用コピー・孤立コピーを削除します。削除中に取得が完了した古い書影は索引へ戻しません。ファイル削除失敗は明示操作へ返し、全削除成功を表示しません。Bookレコード削除後に登録写真の削除が失敗する場合は部分完了を案内します。残る登録写真は図書データ初期化の再試行（残る図書も対象）、検索用コピーは設定の検索準備の再試行で回収します。これらはユーザーが別に書き出したバックアップファイルやOS側のバックアップを削除するものではありません。調整情報が破損・欠落して通常のバックアップを書き出せない場合は、調整情報を除いて図書・利用者・貸出記録・登録写真を保存するか確認します。黙って除外しません。このバックアップを復元すれば調整情報は再準備できますが、失われた手動範囲は再調整が必要です。

## 通信・権利・配布前の残件

- カメラ画像・特徴量の推論と照合は端末内。API書誌検索・URL書影の取得には通信が必要です。既存の任意Firebase送信もあるため、アプリ全体が常に無通信という意味ではありません。
- 楽天書影由来の特徴量を永続保存して蔵書照合に使う許諾は、公開条件から確認できていません。現在の索引経路を今回の設計整理で変更・停止していません。バックアップに書影由来の調整画像が含まれる場合も同じ未解決条件が及びます。
- FastViTのライセンス本文と関連ACKNOWLEDGEMENTS原文を同梱し、設定のライセンス画面に表示します。出典はモデルmetadataが指定する固定版 [`8af5928238cab99c45f64fc3e4e7b1516b8224ba`](https://github.com/apple/ml-fastvit/tree/8af5928238cab99c45f64fc3e4e7b1516b8224ba) の [ACKNOWLEDGEMENTS](https://github.com/apple/ml-fastvit/blob/8af5928238cab99c45f64fc3e4e7b1516b8224ba/ACKNOWLEDGEMENTS)。同梱ファイル `Resources/FastViT-ACKNOWLEDGEMENTS.txt` のSHA-256は `f2347dec17946d74f6269a6fa429032f76c9e5e6389af15ad42a66978f031d95` です。これは表記の補完であり、各条項のモデルへの適用範囲や、他モデル・SDK・楽天書影の権利条件を解決したとの判断ではありません。
- 公開プライバシーポリシーは本変更では未更新。カメラ画像、保存する特徴量・調整画像、バックアップ、保持・削除の実装に沿った追記と公開が配布前に必要です。
- 実表紙、類似表紙、未登録本を含む200冊以上の定量精度は未確認。合成画像テストやUIホストは実物の認識精度の証拠ではありません。
